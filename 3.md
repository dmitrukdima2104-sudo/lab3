### Рівень 1. Базові операції модифікації

#### Крок 1. Створення структури бази даних
Створено базу даних для системи управління бібліотекою з основними таблицями (`authors`, `books`, `readers`, `lendings`) та обмеженнями цілісності.

```sql
DROP TABLE IF EXISTS audit_log CASCADE;
DROP TABLE IF EXISTS reservations CASCADE;
DROP TABLE IF EXISTS lendings CASCADE;
DROP TABLE IF EXISTS readers CASCADE;
DROP TABLE IF EXISTS books CASCADE;
DROP TABLE IF EXISTS authors CASCADE;

CREATE TABLE authors (
    author_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    birth_year INTEGER CHECK (birth_year >= 1000 AND birth_year <= 2026),
    country VARCHAR(50)
);

CREATE TABLE books (
    book_id SERIAL PRIMARY KEY,
    isbn VARCHAR(17) UNIQUE NOT NULL,
    title VARCHAR(200) NOT NULL,
    author_id INTEGER NOT NULL REFERENCES authors(author_id) ON DELETE RESTRICT,
    publication_year INTEGER CHECK (publication_year >= 1450),
    genre VARCHAR(50),
    total_copies INTEGER DEFAULT 1 CHECK (total_copies >= 0),
    available_copies INTEGER DEFAULT 1 CHECK (available_copies >= 0),
    CHECK (available_copies <= total_copies)
);

CREATE TABLE readers (
    reader_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    library_card_number VARCHAR(20) UNIQUE NOT NULL,
    status VARCHAR(20) DEFAULT 'Active' CHECK (status IN ('Active', 'Blocked', 'Inactive'))
);

CREATE TABLE lendings (
    lending_id SERIAL PRIMARY KEY,
    book_id INTEGER NOT NULL REFERENCES books(book_id) ON DELETE RESTRICT,
    reader_id INTEGER NOT NULL REFERENCES readers(reader_id) ON DELETE RESTRICT,
    lending_date DATE DEFAULT CURRENT_DATE,
    due_date DATE NOT NULL CHECK (due_date > lending_date),
    return_date DATE CHECK (return_date IS NULL OR return_date >= lending_date)
);
```

### Рівень 2. Розширена функціональність

#### Крок 7. Додавання нових таблиць (бронювання та аудит)
Розширено базу даних додатковими сутностями `reservations` та `audit_log`.

```sql
CREATE TABLE reservations (
    reservation_id SERIAL PRIMARY KEY,
    book_id INTEGER NOT NULL REFERENCES books(book_id) ON DELETE CASCADE,
    reader_id INTEGER NOT NULL REFERENCES readers(reader_id) ON DELETE CASCADE,
    status VARCHAR(20) DEFAULT 'Active'
);

CREATE TABLE audit_log (
    log_id SERIAL PRIMARY KEY,
    table_name VARCHAR(50) NOT NULL,
    operation VARCHAR(10) NOT NULL,
    record_id INTEGER NOT NULL,
    old_data JSONB,
    new_data JSONB,
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### Крок 9. Використання SAVEPOINT
Демонстрація часткового відкату транзакції при виникненні помилки.

```sql
BEGIN;
INSERT INTO authors (first_name, last_name, birth_year, country) VALUES ('Ольга', 'Кобилянська', 1863, 'Україна');

SAVEPOINT after_author;

INSERT INTO books (isbn, title, author_id, publication_year) VALUES ('978-966-03-4561-2', 'Дублікат', LASTVAL(), 1905);

ROLLBACK TO SAVEPOINT after_author;

INSERT INTO books (isbn, title, author_id, publication_year, genre, total_copies, available_copies) 
VALUES ('978-966-03-4567-4', 'Земля', LASTVAL(), 1902, 'Роман', 3, 3);

COMMIT;
```

#### Крок 11. Тригери для аудиту
Створено тригер для автоматичного збереження історії змін у форматі JSONB.

```sql
CREATE OR REPLACE FUNCTION log_books_changes() 
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'UPDATE' THEN
        INSERT INTO audit_log (table_name, operation, record_id, old_data, new_data)
        VALUES ('books', 'UPDATE', NEW.book_id, row_to_json(OLD)::jsonb, row_to_json(NEW)::jsonb);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER books_audit_trigger 
AFTER UPDATE ON books 
FOR EACH ROW EXECUTE FUNCTION log_books_changes();

UPDATE books SET available_copies = 5 WHERE book_id = 1;
SELECT * FROM audit_log;
```

## ❓ Відповіді на контрольні запитання

1. **Різниця між INSERT, UPDATE та DELETE і їх обмеження:**  
   `INSERT` додає нові рядки, `UPDATE` змінює наявні дані, `DELETE` вилучає рядки з таблиці. Основні обмеження: унікальність ключів (`PRIMARY KEY`, `UNIQUE`), обмеження типів та перевірок (`CHECK`), а також посилальна цілісність (`FOREIGN KEY`).

2. **Важливість умови WHERE в UPDATE та DELETE:**  
   Без умови `WHERE` оператор `UPDATE` оновить абсолютно всі рядки в таблиці, а `DELETE` повністю очистить її вміст, що призведе до втрати даних.

3. **Що таке транзакція та властивості ACID:**  
   Транзакція — це неподільна логічна група операцій.
   * **Atomicity (Атомарність):** виконуються всі операції або жодна.
   * **Consistency (Узгодженість):** збереження всіх обмежень цілісності БД.
   * **Isolation (Ізольованість):** паралельні транзакції не впливають одна на одну.
   * **Durability (Довговічність):** результат підтвердженої транзакції зберігається остаточно.

4. **Різниця між COMMIT та ROLLBACK:**  
   `COMMIT` зберігає всі внесені транзакцією зміни в базі даних. `ROLLBACK` скасовує всі зміни, зроблені від початку `BEGIN`.

5. **Точки збереження SAVEPOINT:**  
   Дозволяють зробити мітку у транзакції та виконати частковий відкат (`ROLLBACK TO SAVEPOINT`) при помилці на певному кроці без скасування всієї транзакції.

6. **Типи обмежень цілісності:**  
   `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK`, `NOT NULL`.

7. **Каскадні операції та їх поведінка:**  
   Автоматично оновлюють або видаляють дочірні записи при зміні батьківського запису (`CASCADE`). Інші варіанти: `SET NULL`, `SET DEFAULT`, `RESTRICT` (заборона дії).

8. **Роль тригерів у базі даних:**  
   Тригери автоматично виконують збережений код при подіях `INSERT`, `UPDATE` чи `DELETE`, що використовується для логування аудиту, складної валідації та обчислень.

9. **Необхідність блокування записів:**  
   Захищає від аномалій при одночасному паралельному доступі двох користувачів до того самого рядка (запобігає race conditions та lost update).

10. **Рівні ізоляції транзакцій:**  
    Визначають ступінь захисту від аномалій паралелізму (`READ UNCOMMITTED`, `READ COMMITTED`, `REPEATABLE READ`, `SERIALIZABLE`).
